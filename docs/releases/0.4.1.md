# Victual 0.4.1

**Tag `v0.4.1`, on `master` at the commit that merges this record.** It follows
[0.4.0](0.4.0.md). The release spans the 91 pull requests merged between `v0.4.0` and
`b69f5a62` (PR 707 and PRs 773–956), most of them the remediation of the 2026-10-12 audit and
the 2026-10-13 bug bash. It adds five migrations (0308–0312), tightens several read and write
permissions, and corrects a large part of the OpenAPI contract.

## What changed

| Change | Effect for an operator or client |
|---|---|
| **Migration 0308 and the `MASTER_DATA_ADD` permission** ([issue 742](https://github.com/datagen24/victual/issues/742), PRs [883](https://github.com/datagen24/victual/pull/883)–[887](https://github.com/datagen24/victual/pull/887), [ADR-0043](../adr/0043-creating-shared-master-data-is-a-right-below-master-data-edit.md)). | A new permission below `MASTER_DATA_EDIT` lets an account create products, barcodes, locations, quantity units, product groups and shopping locations without editing or deleting them. No seeded role gains it; grant it explicitly. The external barcode lookup needs only `STOCK_VIEW` without `add`, and `MASTER_DATA_ADD` with `add=true`; it never overwrites a stored picture. Legacy imports replay the permission row. |
| **Chores and tasks are created and edited under their domain rights** ([PR 884](https://github.com/datagen24/victual/pull/884), ADR-0043 decision 7). | `POST`/`PUT /api/objects/chores` need `CHORES`, and `tasks` need `TASKS`. An account that holds `MASTER_DATA_EDIT` without `CHORES` or `TASKS` **loses** chore and task create and edit; the seeded Adult role gains them. Delete and chore merge stay with `MASTER_DATA_EDIT`. |
| **Stock bookings refuse a caller without `STOCK_VIEW` before booking** ([issue 785](https://github.com/datagen24/victual/issues/785), [PR 834](https://github.com/datagen24/victual/pull/834)). | Add, consume, transfer, open, inventory, stock-entry edit and measure, and both weigh routes answer 403 before any write. Before, the booking committed and then the caller got 403. A key with the booking permission alone must also be granted `STOCK_VIEW`. |
| **Product merge requires both `STOCK_EDIT` and `MASTER_DATA_EDIT`** ([issue 782](https://github.com/datagen24/victual/issues/782), PRs [833](https://github.com/datagen24/victual/pull/833), [840](https://github.com/datagen24/victual/pull/840)). | The seeded Adult role can no longer merge products. The products page disables the Merge item for a user missing either right. |
| **Product merge keeps conversions and consumption data consistent** (PRs [880](https://github.com/datagen24/victual/pull/880), [921](https://github.com/datagen24/victual/pull/921), [955](https://github.com/datagen24/victual/pull/955); issue 901). | A merge repoints and rescales the removed product's consumption recipe lines, mappings and event lines instead of deleting them. It is refused with 400, changing nothing, when a row with its own unit would convert to a different stock amount afterwards, or when the stock units differ and no resolved factor-1 conversion joins them. |
| **Battery, equipment and custom-entity reads require their view rights** (PRs [875](https://github.com/datagen24/victual/pull/875), [906](https://github.com/datagen24/victual/pull/906), [910](https://github.com/datagen24/victual/pull/910), [ADR-0035](../adr/0035-batteries-equipment-calendar-and-custom-entities-require-view-permissions.md)). | `/api/objects` reads of `batteries` and `battery_charge_cycles` need `BATTERIES_VIEW`, `equipment` and equipment manuals need `EQUIPMENT_VIEW`, and battery calendar events need `BATTERIES_VIEW`. `userobjects` and `userentity-*` userfield reads need `MASTER_DATA_EDIT`. A caller without the right, the Child role included, gets 403 where it got rows. Battery labels need `BATTERIES_VIEW` instead of `BATTERIES`. |
| **A userfile is readable only by callers every owning record admits** (part of [issue 905](https://github.com/datagen24/victual/issues/905), PRs [919](https://github.com/datagen24/victual/pull/919), [956](https://github.com/datagen24/victual/pull/956); [ADR-0048](../adr/0048-a-userfile-is-readable-only-by-callers-every-owning-record-admits.md), Proposed). | `GET /api/files/userfiles/{fileName}` was served to any authenticated caller who knew the stored name. It answers 403 unless the caller can read every record that references the file; an unreferenced file is `ADMIN` only. This is a partial fix: a `MASTER_DATA_EDIT` holder can still clear or delete the owning record and then read the file ([issue 920](https://github.com/datagen24/victual/issues/920), open). |
| **The shopping list withholds product userfields from callers without stock view** ([PR 927](https://github.com/datagen24/victual/pull/927)). | `GET /shoppinglist` with only `SHOPPINGLIST_VIEW` no longer renders product and product-group userfield values or file names. |
| **Migration 0309: unit changes and conversion factors** ([PR 879](https://github.com/datagen24/victual/pull/879), [PR 914](https://github.com/datagen24/victual/pull/914); issues 849, 853, 866, 868). | Conversion factors must be positive and finite; the migration refuses, with a report and no repair, a database that holds another factor, and the legacy importer refuses one before truncating. Changing a product's stock unit rescales its stock-unit consumption mappings and event lines. Bulk ledger updates rebuild the price caches once per product instead of once per row. |
| **Migration 0310: consumption events** ([PR 882](https://github.com/datagen24/victual/pull/882); issues 863, 864, 867, 870). | The event list includes old events a stock-side undo changed. One stock transaction can no longer count as two events; the migration refuses, with a report, a database that already holds such a pair. Deleting a location no longer fails because an event line names it. A new index on `stock_log (transaction_id)` speeds every per-transaction read. |
| **Migration 0311: skipped chores and undo** ([PR 876](https://github.com/datagen24/victual/pull/876); issues 856, 865). | A skipped chore execution consumes nothing and needs no `STOCK_CONSUME`. Undoing an execution restores the reschedule date and assignee that tracking cleared, for executions recorded after the upgrade. `chores_log` gains two nullable fields. Both behaviours differ from upstream grocy 4.6.0 on purpose. |
| **Migration 0312: the chore consume flag is 0 or 1** ([PR 940](https://github.com/datagen24/victual/pull/940), issue 923). | Any other value of `chores.consume_product_on_execution` is refused on write. The migration and the legacy importer refuse, with a report and no repair, a database that holds another value. |
| **Stock input checks** (PRs [792](https://github.com/datagen24/victual/pull/792), [823](https://github.com/datagen24/victual/pull/823)). | A non-string `transaction_type` on add or consume, and a null or non-numeric `gross_amount` on the weigh routes, answer 400. A JSON `null` gross amount booked an inventory correction to zero before. |
| **Barcode lookup plugin output is checked** (PRs [845](https://github.com/datagen24/victual/pull/845), [911](https://github.com/datagen24/victual/pull/911), [949](https://github.com/datagen24/victual/pull/949)). | A plugin's non-finite number anywhere, a non-string `name`, or a purchase-to-stock factor whose value or inverse is not a normal positive double answers 400 and writes nothing. Before, some of these returned 500 and left the product, barcode and conversion rows behind. |
| **Legacy import restores the view permissions** ([issue 784](https://github.com/datagen24/victual/issues/784), [PR 789](https://github.com/datagen24/victual/pull/789)). | After an import, `BATTERIES_VIEW`, `CALENDAR_VIEW` and `EQUIPMENT_VIEW` were missing for everyone, `ADMIN` included. The importer replays migration 0299's rows. Fresh installs and upgrades were not affected. |
| **InfluxDB outbox** (PRs [874](https://github.com/datagen24/victual/pull/874), [918](https://github.com/datagen24/victual/pull/918)). | A row InfluxDB rejects no longer fails the rows batched with it; it is dead-lettered only when another row of the same drain was accepted. `bin/victual-publish-state --drain` exits 1 when a drain makes no progress. `bin/victual-publish-state --requeue-dead` puts dead-lettered rows back in the queue, with a dry run; see the [MQTT guide](../manual/operator/home-assistant-mqtt.md). |
| **Label rendering and printing** (PRs [878](https://github.com/datagen24/victual/pull/878), [881](https://github.com/datagen24/victual/pull/881), [925](https://github.com/datagen24/victual/pull/925); issues 846, 857, 858, 899). | An unrenderable request is settled as `invalid` instead of heading the queue on every poll, and its waiting print jobs are dead-lettered with a reason. The renderer's claim poll collects expired previews without claims waiting on each other. The web print button keeps one idempotency key per target and printer across a reload, ending spurious 409s and duplicate prints. |
| **MCP sidecar error classes** (PRs [872](https://github.com/datagen24/victual/pull/872), [935](https://github.com/datagen24/victual/pull/935); issues 850, 859, 895). | A write that timed out, was reset, or got 502/504 reports the new `outcome_unknown` and is not retried, because it may have been applied. A 503 reports `victual_unavailable`. The request timeout covers the response body. The `shopping_list` tool is listed only to keys that also hold `STOCK_VIEW`. |
| **Helm chart hardening** ([PR 873](https://github.com/datagen24/victual/pull/873); issues 851, 852, 861, 862). | Each label-worker pod mounts only its own credential key. `victual` and `victual-mcp` roll when their ConfigMap or an inline Secret changes; with `existing` or `onepassword` secrets, restart them yourself. No pod mounts a service account token. `BOOTSTRAP_*` settings are refused in values. |
| **Nix image nginx headers** ([PR 877](https://github.com/datagen24/victual/pull/877), issue 855). | Static `.mjs` and asset responses carry `X-Content-Type-Options`, `X-Frame-Options` and `Referrer-Policy`, which they had dropped, and `/packages/<pkg>/.<dotfile>` is denied instead of served. |
| **OpenAPI contract** (`victual.openapi.json`; issue 796 and PRs 791, 797, 810–812, 814, 815, 817–820, 822, 824, 828, 915, 934, 939, 943, 945). | The document declares OAS 3.2.0, which CI checks, and describes the keys, errors, credentials and media types the server uses. A generated client sees: `GET /objects/{entity}` unions as `anyOf`, with members for `stock_log`, `product_barcodes_view` and `uihelper_shopping_list`; `permission_id`, not `permissions_id`; no `ChoreDetailsResponse.track_count`. Regenerate any client built from 0.4.0. Responses change only as the rows above say. |
| Decision records. | [ADR-0038](../adr/0038-kubernetes-deployments-ship-as-a-helm-chart.md) and ADR-0043 are accepted. ADR-0045 to ADR-0049 are new and Proposed, and ADR-0027 and ADR-0044 gained maintainer responses or corrections and stay Proposed. Accepted ADR-0035 and ADR-0036 carry dated amendments. A Proposed record constrains nothing. |

Migrations 0308–0312 are PostgreSQL-only, as every migration above 0265 is. Migrations 0309,
0310 and 0312 stop with a report, and change nothing, on a database that holds a value their new
constraint forbids. Read each migration's header comment before upgrading a database that holds
data.
