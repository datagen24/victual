# Victual 0.1.0-MVP

**Tag `v0.1.0-MVP`, 2026-09-19, on `master` at the commit that merges this record.** The
first tagged version of the fork. It replaces the `4.6.0` that `version.json` carried since
the cut from [grocy 4.6.0](https://github.com/grocy/grocy/releases/tag/v4.6.0)
(2026-03-06): every image the flake builds, every manifest under `deploy/`, and the
version `GET /api/system/info` reports now say `0.1.0-MVP`.

The version line stays at 0.x while this release runs in the household it was built for.
1.0 follows that soak, not a date. The checks below are what "verified working" meant on
the day; the [open verification](#open-verification) section is what it did not yet mean.

## What the release is

The minimum that serves the fork's goals in the [root README](../../README.md): a
PostgreSQL-only, stateless Victual that runs from Nix-built images, publishes to Home
Assistant, prints labels, models the household's locations and products, and answers an
assistant through a read-only MCP sidecar. Delivery status by plan is the
[plan index](../plans/README.md); this section is orientation, not the authority.

| Area | In this release |
|---|---|
| Engine | PostgreSQL only ([ADR-0008](../adr/0008-postgresql-only-runtime-engine.md)); SQLite is an import format read by `bin/victual-db-import`. Migrations 0256–0287 above the squashed baseline, PostgreSQL-only above 0265. |
| Runtime | No persistent application volume (plans [01](../plans/01-file-storage.md), [10](../plans/10-cold-start-statelessness.md)): files in the database, auth state in the database, `bin/victual-migrate` as the deployment's init step, a generated first-administrator password with a forced change. |

## Accepted differences from upstream grocy 4.6.0

The parity suite reports nothing unexplained because each of these is recorded in
`.devtools/parity/harness/lib/accepted.js` with the decision that made it. They are the
places the wire differs from upstream on purpose, and a client written against upstream
should expect them.

- Additive columns on existing entities from plans 03, 05, 08, 23, 28, 29, 30, 31 and the
  label import state ([ADR-0021](../adr/0021-label-templates-are-application-data.md)),
  each accepted only on the routes its plan added it to.
- `GET /api/users/{id}/permissions` returns the whole permission tree with
  `has_permission`, `parent`, `permission_name` and `via_roles` (plan 19), and the
  permission set carries the fork's added leaves.
- `last_price`, price history order and `avg_price` have a defined answer where upstream's
  `LIMIT 1` had no tie-break and SQLite truncated the average
  ([issue 46](https://github.com/datagen24/victual/issues/46), migration 0261).
- Error text is the fork's own where upstream quoted a driver's SQLSTATE
  ([plan 11](../plans/11-api-error-handling.md)).
- `grocy_version` in `GET /api/system/info` is `victual_version`
  ([plan 16](../plans/16-project-rename.md)); the `GROCY-API-KEY` header and the
  query-string key are gone.
- The layout's logout control is a POST form (sweep S8), and `/stockentries` carries the
  measurement dialog of plan 28.

## Known limitations

- **Line coverage is 47.30% against a 75% floor.** The ratchet in CI keeps it from
  falling; [issue 192](https://github.com/datagen24/victual/issues/192) is the backlog.
- **The MCP sidecar is read-only.** `add_to_shopping_list`, `consume_product` and
  `purchase_product` are specified and unbuilt until read-only use is proven
  ([issue 209](https://github.com/datagen24/victual/issues/209)).
- **Barcode lookup is Open Food Facts only**; the US sources of plan 09 wait on the kitchen
  experiment ([issue 80](https://github.com/datagen24/victual/issues/80)).
- **Nine Low or Informational sweep findings are open or part-open** (S13, S14, S15, S16,
  S19, S20, S22, S24, S26), each with its reasoning in the
  [security sweep](../security-sweep.md). Every Medium and High is fixed.
- **The shipped image accepted 32 MB uploads until 2026-09-19** (`aa9b1712` raised it to
  the configured 64 MB); the clamp warning that php-fpm wrote on every request is
  [PR 221](https://github.com/datagen24/victual/pull/221), merged before the tag
  ([issue 217](https://github.com/datagen24/victual/issues/217)).
- **Migrations 0001–0255 and the differential harness's SQLite side** are retained
  though retirable; [plan 24](../plans/24-sqlite-runtime-retirement.md) lists both.

## Installing and upgrading

- New installation: the manual's [Getting started](../manual/getting-started.md) and
  [deploy/README.md](../../deploy/README.md). Images are `victual-{app,web,migrate,label-renderer,label-worker,mcp}:0.1.0-MVP`,
  built with `nix build` per [nix/README.md](../../nix/README.md).
- From grocy or an earlier Victual SQLite database: `bin/victual-db-import`, within the
  migration span [db/pgsql/README.md](../../db/pgsql/README.md) states.
- From a pre-release checkout of this fork: pull the tag and run `bin/victual-migrate`,
  per [Updating and migrations](../manual/operator/updating-migrations.md). An installation
  still seeded with `admin`/`admin` is made to change that password at its next login.
