# Victual 0.4.0

**Tag `v0.4.0`, on `master` at the commit that merges this record.** It follows
[0.3.2](0.3.2.md). It is a minor version because it adds three migrations (0305–0307), adds
routes and a large part of the OpenAPI contract, and adds the private consumption recipes of
[plan 22](../plans/22-medication-tracking.md). The release spans PRs 688–759, the commits
between `v0.3.2` and `26f2ff07`.

## What changed

| Change | Effect for an operator or client |
|---|---|
| **Migration 0305: private consumption recipes** ([issue 698](https://github.com/datagen24/victual/issues/698), PRs 734–736, [ADR-0040](../adr/0040-consumption-recipes-are-private-rows-with-scoped-shares.md), [ADR-0041](../adr/0041-consumption-events-have-a-source-identity-and-explicit-reconciliation.md)). | A person can keep a private list of products they consume together, such as a prescription, share it with named users at `read` or `edit`, and record its consumption manually. New tables hold the recipes, their lines, shares and consumption events. |
| **Migration 0306: external consumption events and reconciliation** ([issue 700](https://github.com/datagen24/victual/issues/700), PRs 739, 741, 743). | An external client can report a consumption event with a stable source event id. Reporting it twice books it once. A reconciliation inbox holds events the household has not yet mapped to a recipe or product. |
| **Migration 0307: refill tracking** ([issue 701](https://github.com/datagen24/victual/issues/701), PRs 748, 749, 751, 755). | A consumption recipe gains refill history, reorder rules and notice acknowledgements, and a prescription refills page. |
| **Organizer workflow** ([issue 699](https://github.com/datagen24/victual/issues/699), PRs 738, 744). | Tests and documentation cover a weekly organizer workflow. A consume request with a malformed `location_id` is now refused with 400. |
| **MCP sidecar write tools** ([PR 688](https://github.com/datagen24/victual/pull/688)): `add_to_shopping_list`, `consume_product`, `purchase_product`. | The sidecar is no longer read-only. [ADR-0039](../adr/0039-the-mcp-sidecar-reads-its-configuration-from-victual.md), Proposed, proposes that its configuration live in Victual's database ([PR 689](https://github.com/datagen24/victual/pull/689)). |
| **Session writes behind a reverse proxy** ([PR 758](https://github.com/datagen24/victual/pull/758)). | A session write that the origin check refused as cross-origin behind a reverse proxy, now succeeds. The own origin's host and port come from the request's `Host` header. |
| **OpenAPI contract** (`victual.openapi.json`). | The contract grows by the routes above. Regenerate any client built from 0.3.2. |
| Decision records. | [ADR-0015](../adr/0015-medication-records-never-advises.md), 0040, 0041 and 0042 are accepted, ADR-0016 is rejected, and ADR-0043 and ADR-0044 are Proposed. A Proposed record constrains nothing. |

Migrations 0305–0307 are PostgreSQL-only, as every migration above 0265 is. The row for each
migration's own header comment states what it adds; read it before upgrading a database that
holds data.
