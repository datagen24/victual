# Victual 0.3.0

**Tag `v0.3.0`, on `master` at the commit that merges this record.** It follows
[0.2.0-MVP](0.2.0-MVP.md) and closes milestone 0.3.0 (nine issues, all closed). The `-MVP`
suffix is dropped: this is the first version string without it.

This is a minor version because it adds sixteen migrations (0289–0304), changes the wire
format of every timestamp the API sends, and changes what undo and stock maintenance do. It
is also the first release whose images are meant for a real cluster: the Talos
Raspberry Pi apply landed in
[PR 661](https://github.com/datagen24/victual/pull/661), with no production data yet.

## What changed

The release spans PRs 482–669, 424 commits. The table lists what an operator or client can
notice; the bug-sweep fixes that only turn a 500 into a 4xx or close a permission gap are
grouped in the last row.

| Change | Effect for an operator or client |
|---|---|
| **Migration 0301: every timestamp is an instant** ([issue 650](https://github.com/datagen24/victual/issues/650), [PR 652](https://github.com/datagen24/victual/pull/652), [ADR-0027](../adr/0027-timestamps-are-local-strings-documented-booleans-are-booleans.md) decision 2). | **The wire changes.** Timestamps are RFC 3339 UTC, `2026-10-04T18:30:00.000000Z`, where they were local `Y-m-d H:i:s` strings. A client or Home Assistant template that parsed the old text must change. Stored wall clocks are read in the zone in force when the migration runs. The migration rolls back whole on a refusal. See [Migration 0301](../manual/operator/updating-migrations.md#migration-0301-timestamps-become-instants). |
| Migration 0304: booking lineage ([issue 665](https://github.com/datagen24/victual/issues/665), [ADR-0036](../adr/0036-stock-quantities-are-attributed-to-the-bookings-that-added-them.md), [PR 669](https://github.com/datagen24/victual/pull/669)). | Undo finds a booking's units by what it booked, and accepts undos it used to refuse. `bin/victual-compact-stock` stops rewriting `stock_id` and needs a different grant list. `bin/victual-db-import` rebuilds lineage and refuses an import that does not check out. |
| Migration 0290 and the maintenance command ([PR 580](https://github.com/datagen24/victual/pull/580), [ADR-0033](../adr/0033-stock-rows-merge-only-in-maintenance-for-non-expiring-rows.md)). | Stock rows merge only when you run `bin/victual-compact-stock`. Nothing schedules it. |
| Migration 0303: stock-entry label retirement events ([issue 612](https://github.com/datagen24/victual/issues/612), [PR 663](https://github.com/datagen24/victual/pull/663), [ADR-0037](../adr/0037-an-undo-of-a-whole-row-consumption-revives-the-stock-entry-label-it-retired.md)). | Undoing a whole-row consumption revives the stock-entry label it retired. |
| Migration 0302 ([PR 660](https://github.com/datagen24/victual/pull/660)). | `stock_edited_entries` is linear in the ledger. A booking cost 48 s at 19,416 rows before; 0.29 s after. Same rows. |

## Open verification and known limitations

- The upgrade rehearsal has not run through migrations 0303 and 0304.
- The 0.2.0-MVP limits stand: the household cluster has not run on live data, a label
  worker image reaching the printer from a cluster, Home Assistant surviving the pod at zero,
  and the MCP replay tests. Plan 35 (the Home Assistant add-on) is specified and not built.
- [Issue 648](https://github.com/datagen24/victual/issues/648): three
  `GET /objects/{entity}` entities decode under a schema that is not theirs. It is open and
  not in this milestone.
- ADR-0027 stays Proposed. Its prerequisite 6, regenerating `victual-kit` from this release's
  document, follows this release.
- Migration 0301 has no reverse. To go back, restore the backup taken before the upgrade.

## Installing and upgrading

Images are `ghcr.io/datagen24/victual-{app,web,migrate,label-renderer,label-worker,mcp}:0.3.0`
for `linux/amd64` and `linux/arm64`.

From 0.2.0-MVP: take a `pg_dump` backup, stop the application and the label workers, run
`bin/victual-migrate`, start the new version, and run `bin/victual-publish-state`. Read
[Updating and migrations](../manual/operator/updating-migrations.md) first: 0301 reads
stored wall clocks in the server's configured zone, and 0304 changes the grants
`bin/victual-compact-stock` needs. The database server must be PostgreSQL 15 or newer.

For migration 0303, follow the [stock-entry label retirement upgrade instructions](../manual/operator/updating-migrations.md#migration-0303-stock-entry-label-retirement-events).
They describe deployment order, legacy labels and compatibility consequences.
