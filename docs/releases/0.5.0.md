# Victual 0.5.0

**Tag `v0.5.0`, on `master` at the commit that merges this record.** It follows
[0.4.4](0.4.4.md). It is a minor version because it adds six migrations (0313–0318), changes
some response shapes and accepted inputs (see [Compatibility](#compatibility)), and completes
[plan 22](../plans/22-medication-tracking.md), the v0.5.0 milestone. The release spans PRs
975–1003, the merges between `v0.4.4` and `56abf0a0`.

## What changed

| Change | Effect for an operator or client |
|---|---|
| Every double precision and numeric column now refuses NaN and infinities ([PR 979](https://github.com/datagen24/victual/pull/979), issue 916). | A write of `"NaN"`, `"Infinity"`, `"-Infinity"`, `"inf"` or an out-of-range JSON number gets 400 "The <field> must be a finite number". Before, it was stored and later reads of the record returned 500. The SQLite importer refuses such sources and names each column. |
| Numeric body fields are validated on the raw value, before the HTML purifier rewrites it ([PR 976](https://github.com/datagen24/victual/pull/976), issue 946). | Strings holding control characters, character references or markup get 400 with nothing written. `permission_id` values such as `"\v2"` no longer grant permission 2. Non-numeric `stock_label_type`, `recipe_id` and shopping-list amounts or ids, and nonpositive shopping-list amounts or ids, get 400. |
| A write that changes a userfile's owners now requires read access to every owner the file had before the write ([PR 978](https://github.com/datagen24/victual/pull/978), issue 920). | A `MASTER_DATA_EDIT` holder who cannot read every owner gets 403 `USERFILE_OWNER_READ` for userfield value changes, cascading deletes, merges, file deletes and same-name uploads. Derivative names (`<name>__downscaledto<h>x<w>.<ext>`) get 400 at upload and as userfield values. |
| The five stock bookings accept an optional `Idempotency-Key` header on the direct and by-barcode routes ([PR 980](https://github.com/datagen24/victual/pull/980), issue 775). | A retry with the same key and body returns the original transaction with `Idempotent-Replayed: true`. A reused key with a different request gets 409 `idempotency_conflict`; an unfinished one gets 409 `idempotency_in_progress`. `GET /api/system/info` gains `stock_booking_idempotency`. New `transaction_id` values are 32 lowercase hex characters. |
| Stock prices now tell an unknown price from a known zero, and existing zeros are marked as unknown ([PR 984](https://github.com/datagen24/victual/pull/984), [PR 985](https://github.com/datagen24/victual/pull/985), issue 774). | An unknown price is `null`, a known zero is `0`, and the field is absent without `STOCK_PRICES_VIEW`. `last_price`, `current_price` and `oldest_price` can become `null`. `avg_price` now counts free purchases. New booleans `value_incomplete` and `stock_value_incomplete` say whether a value is complete. `bin/victual-db-import` gains `--legacy-zero-prices=unknown|known`. |
| The stock entries page, the stock entry edit form, the meal plan, weighing and InfluxDB publishing now also read a marked `0` as unknown ([PR 996](https://github.com/datagen24/victual/pull/996), [PR 997](https://github.com/datagen24/victual/pull/997), issue 990). | These pages show no price, or a "No price information" marker, where they showed `0`. Weighing books `null` when no price is known. A marked purchase writes no `price_paid` point to InfluxDB. The API response shape is unchanged. |
| A drain no longer stops at a batch made up only of unreadable outbox rows ([PR 981](https://github.com/datagen24/victual/pull/981), issue 928). | `bin/victual-publish-state --drain` sets those rows aside, delivers the rows behind them and exits 0. It exits 1 only when delivery fails. |
| The MCP booking tools report a 2xx answer without a transaction row as `outcome_unknown` ([PR 982](https://github.com/datagen24/victual/pull/982), issue 937). | `consume_product` and `purchase_product` return `outcome_unknown` with `victual_status` and check-before-retry advice. Before, they returned `victual_error` saying a retry would not help. |
| Label worker registration refuses NUL bytes anywhere in the request ([PR 983](https://github.com/datagen24/victual/pull/983), issue 944). | `POST /api/labels/register` answers 422 `LabelRefusal` with `invalid_value` and a dotted `field` path. Before, a NUL in `capability_document` got a generic 400 and a NUL in `driver_id` got 200. |
| A product merge now blocks writes to quantity unit conversions until it commits ([PR 998](https://github.com/datagen24/victual/pull/998), issue 930). | A conversion written during a merge can no longer slip past the merge's conflict check. Conversion writes wait while a merge transaction is open. |
| Charge tracking returns only the new cycle's id to a caller without `BATTERIES_VIEW` ([PR 999](https://github.com/datagen24/victual/pull/999), issue 908). | `POST /api/batteries/{batteryId}/charge` returns `{"id": <id>}` to a caller with only `BATTERIES_TRACK_CHARGE_CYCLE`. Callers with `BATTERIES_VIEW` still get the full row. The id is enough to undo the cycle. |
| Stock shortfalls on the shopping list now require `STOCK_VIEW` ([PR 1000](https://github.com/datagen24/victual/pull/1000), issue 933). | Without `STOCK_VIEW`, the page hides the below-minimum count, row markers, filter and add action. `POST /api/stock/shoppinglist/add-missing-products` answers 403 where it answered 204. Barcodes stay visible with `SHOPPINGLIST_VIEW`. |
| A conversion write is refused when a written or resolved factor, or its inverse, leaves the normal double range ([PR 1001](https://github.com/datagen24/victual/pull/1001), issue 952). | Such a write, including one from a barcode lookup, gets 400 with a specific range message and rolls back. Before, it failed with a generic database error or stored a subnormal inverse. Existing conversions are not rewritten. |
| **Plan 22 is complete** ([issue 703](https://github.com/datagen24/victual/issues/703)). Issues 701, 702 and 742 closed on 2026-10-19, after the native acceptance matrix was re-pinned to the v0.4.4 client ([PR 1003](https://github.com/datagen24/victual/pull/1003), victual-kit PR 44). | The medication inventory, private consumption recipes, external consumption events and refill notices that shipped in [0.4.0](0.4.0.md) are now accepted end to end, with the limitations listed below. No runtime change. |
| Test fixes and documentation: a partial-undo fixture, numeric boundary cases, and the plan 22 native client commit record ([PR 975](https://github.com/datagen24/victual/pull/975), issue 942; [PR 977](https://github.com/datagen24/victual/pull/977), issue 950; [PR 1003](https://github.com/datagen24/victual/pull/1003), issue 702). | Tests and documentation only; no runtime effect. |

## Database migrations


- **0313** ([PR 979](https://github.com/datagen24/victual/pull/979)): adds a `<table>_<column>_finite` CHECK to 35 numeric columns. It refuses the upgrade with a report if any column already holds NaN or an infinity.
- **0314** ([PR 980](https://github.com/datagen24/victual/pull/980)): adds the `stock_booking_idempotency_keys` table and a non-unique index on `stock_log.transaction_id`.
- **0315** ([PR 984](https://github.com/datagen24/victual/pull/984)): adds `legacy_zero_price` to `stock` and `stock_log`, marks every existing price of 0, and records the counts in the new `price_interpretation_reports` table.
- **0316** ([PR 985](https://github.com/datagen24/victual/pull/985)): adds `stock_current.value_incomplete`, rewrites the price and recipe cost views for differences D1 to D4, and rebuilds both price caches.
- **0317** ([PR 996](https://github.com/datagen24/victual/pull/996)): changes `uihelper_stock_entries` to return `NULL` for a marked price of 0.
- **0318** ([PR 1001](https://github.com/datagen24/victual/pull/1001)): redefines the `quantity_unit_conversions` triggers to refuse factors outside 2^-1022 to 2^1022 with SQLSTATE `VQ952`.

None of these migrations rewrites stored prices or stock rows. Migration 0313 can refuse an upgrade: repair the reported rows, then run the migration again. Migration 0314 builds an index on `stock_log` and holds bookings while it runs, up to its 5-second lock timeout.

**Before upgrading.** Back up the database. Migration 0313 refuses the upgrade if any numeric
column holds NaN or an infinity. It names each column and changes nothing. Repair those rows,
then run `bin/victual-migrate` again. The [upgrade rehearsal](0.5.0-upgrade-rehearsal.md) shows
the refusal leaving a database at migration 312, byte-identical.

## Compatibility


**Response shapes**

- `last_price`, `current_price` and `oldest_price` are `null` where they were `0` for a product with no known price. `products_last_purchased.price` can be `null`.
- Raw `stock` and `stock_log` rows return `price: null` for a marked legacy zero.
- `avg_price` and the price history include known `0` purchases, so averages can drop.
- Self-production from a recipe with incomplete costs, inventory corrections and weighing store `null` instead of `0` when no price is known.
- `POST /api/batteries/{batteryId}/charge` returns only `{"id": <id>}` to a caller without `BATTERIES_VIEW`.
- New `transaction_id` values are 32 lowercase hex characters instead of 13. Existing ids stay readable and undoable. Clients must treat the id as opaque.
- `POST /api/labels/register` answers 422 `LabelRefusal` for a NUL byte, where it answered 400 or 200.
- The MCP tools `consume_product` and `purchase_product` return `outcome_unknown` for a 2xx answer without a transaction row, where they returned `victual_error`.
- Additive: `value_incomplete`, `stock_value_incomplete`, the `stock_booking_idempotency` object in `GET /api/system/info`, the `Idempotent-Replayed` response header and the two 409 codes.

**Accepted input**

- Non-finite numbers in any numeric field get 400 instead of being stored.
- Numeric body fields with control characters, character references or markup get 400. Non-numeric `stock_label_type`, `recipe_id` and shopping-list amounts or ids get 400. Nonpositive shopping-list amounts or ids get 400.
- Userfile derivative names get 400 at upload and as userfield values.
- Conversion writes and barcode lookups that would leave the normal factor range get 400.
- Additive: the optional `Idempotency-Key` request header on the five stock bookings.

**Permissions**

- Writes that change a userfile's owners, and deletes or same-name uploads of a referenced file, need read access to every current owner. Otherwise they get 403 `USERFILE_OWNER_READ`.
- `POST /api/stock/shoppinglist/add-missing-products` needs `STOCK_VIEW` in addition to `SHOPPINGLIST_ITEMS_ADD`. The shopping-list shortfall count, markers, filter and add action need `STOCK_VIEW`.
- Battery charge tracking and undo still work without `BATTERIES_VIEW`; only the charge response body changes.

**Configuration**

- No application setting changed. CORS now allows the `Idempotency-Key` request header and exposes `Idempotent-Replayed`.
- `bin/victual-db-import` gains `--legacy-zero-prices=unknown|known` (default `unknown`) and now refuses an unknown option.

**Clients.** `victual-kit` follows released server versions only, because its evidence needs a
live server running that release. It moves to this contract after the tag: the opaque
`transaction_id`, `null` prices, `value_incomplete` and the `Idempotency-Key` header. PRs 980 and
985 named issue 891 for this hand-off. That issue was closed as not planned on 2026-10-19 for
the same reason, so the client side is tracked in `victual-kit`, not here.

## Known limitations

- **Apple Health.** Native acceptance used the iOS Simulator, as the maintainer decided on
  2026-10-11. No real Health store was observed, so identifier changes on edit and delete, late
  delivery and background delivery come from Apple's documentation and the client's design, not
  from observation.
- **Conversions.** A medication mapped in a unit other than its product's stock unit needs a
  quantity unit conversion, and only `MASTER_DATA_EDIT` can create one
  ([ADR-0043](../adr/0043-creating-shared-master-data-is-a-right-below-master-data-edit.md)).
- **Upgrade rehearsal scope.** The rehearsal ran on PostgreSQL 16.15 with PHP 8.5.10 from the
  flake's development shell, not the production images. It is not a backup-restore test.
  PostgreSQL 15 is covered by the `tests` workflow's migration phase.
- **Plan 22 file.** The plan stays at `docs/plans/22-medication-tracking.md` until the tag is
  published. Moving it to `landed/` changes links in 26 files, so it is a separate pull request.
- The rest of the 0.5.0 milestone: issue 703 closes with this record. Issues 987–991 are
  assigned to 0.5.1, and 483, 484, 486, 770, 771 and 796 to 0.6.0.
