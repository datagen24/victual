# Victual 0.1.1-MVP

**Tag `v0.1.1-MVP`, 2026-09-19, on `master` at the commit that merges this record.** A patch
release over [0.1.0-MVP](0.1.0-MVP.md). It changes no schema, adds no migration (0287 is
still the last) and changes no response shape. It fixes how the label endpoints write, and
makes the PostgreSQL minimum a check instead of a sentence.

## What changed

| Change | Effect for an operator or client |
|---|---|
| The label endpoints open their transactions through `DatabaseService::InTransaction()` and advance the changed time after a committed write (`BaseApiController::InRequestTransaction()`, `DatabaseService::MarkDbChanged()`). | `GET /api/system/db-changed-time` now moves after a label write (a template saved, published or archived; a print job issued, reprinted or cancelled; a printer or worker administered). Before, a client polling it kept showing stale data. A label request that arrives inside an open transaction joins it instead of throwing. |
| Worker and renderer polling (claim, heartbeat, registration, printer status, render claim) deliberately does not advance the changed time; a job's own progress does (sent, result, evidence, render result, invalid, failed). | A worker heartbeat does not refresh every open browser. |
| A missing label asset on `GET /api/labels/assets/{id}/bytes` still answers 404. | Unchanged; the check moved out of a manual rollback into the response after the transaction. |
| `PostgresDialect::OnConnected()` refuses a server older than PostgreSQL 15 with a message naming the version it found. | An installation pointed at PostgreSQL 14 or older stops at startup with that message. Before, it reached migration 0273 and failed with a syntax error at `NULLS NOT DISTINCT`. |
| A `suite-floor` CI job runs the differential suite on `postgres:15`. | The stated minimum is the tested minimum. |
| Plans that are finished moved to `docs/plans/landed/` and `retired/`; the six data-model diagrams were regenerated against the current schema (71 tables, 50 views, 65 triggers) and four were added (places, access, labels, printing). | Documentation only. |

The label change is a release rather than a documentation note because the defect was in
shipped code: the label endpoints wrote on the raw connection, outside the application's
transaction and change-tracking layer (described under
[Data access](../data-model.md#data-access)).

## Open verification and known limitations

Unchanged from [0.1.0-MVP](0.1.0-MVP.md#open-verification): the household cluster apply,
a label worker image reaching the printer from a cluster, Home Assistant surviving the pod at
zero, and the MCP replay tests. One addition:

- The renderer's HTTP routes have no scripted test. `.devtools/labels/http-tests.py` covers
  the worker, printer and template routes; the render claim, result, invalid and failed routes
  were exercised by hand for this release.

## Installing and upgrading

Images are `victual-{app,web,migrate,label-renderer,label-worker,mcp}:0.1.1-MVP`. From
0.1.0-MVP, pull the tag and restart; `bin/victual-migrate` applies nothing new. The database
server must be PostgreSQL 15 or newer.
