## What changed

| Change | Effect for an operator or client |
|---|---|
| Application write precision ([PR 966](https://github.com/datagen24/victual/pull/966), issue 951) | PostgreSQL writes preserve the full binary64 value instead of rounding through a 14-significant-digit decimal. Numeric responses can therefore expose additional low-order digits. For example, the `inventory.new_amount` sum for `1e-3` now serializes as `0.001000000000000334`; the response shape and accepted input are unchanged. Clients should treat the field as a number instead of depending on its previous decimal spelling. |
| SQLite REAL import verification ([PR 967](https://github.com/datagen24/victual/pull/967), issue 917) | SQLite REAL values retain their binary64 precision when copied to PostgreSQL. A row/value mismatch is detected inside the target transaction before sequence resynchronization and lineage rebuilding, so that verification failure rolls the target copy back. Keep the SQLite source and target backup through post-copy processing, which remains outside that transaction. |

The release adds no database migration, permission, configuration, or deployment-path
change. It preserves the API response shape and valid input set. The numeric spelling
change above is observable and is documented for clients that compare decimal text.
