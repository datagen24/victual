# Victual 0.5.4

**Tag `v0.5.4`, on `master` at the commit that merges this record.** It follows
[0.5.3](0.5.3.md). It is a patch release, and the reason to install it is the MCP sidecar: an
assistant can now build a household's catalog and count its stock from a conversation, so a
mostly empty database can be filled by walking the pantry. It implements
[ADR-0052](../adr/0052-the-mcp-sidecar-builds-the-catalog-and-the-chart-exposes-it.md)
(Proposed; its acceptance prerequisite 3, a real-client run on production, follows this tag).
Only the sidecar, the Helm chart and documentation changed. Victual itself and its schema did
not.

## What changed

| Change | Effect for an operator or client |
|---|---|
| ADR-0052 and its open-question answers ([PRs 1065](https://github.com/datagen24/victual/pull/1065) and [1066](https://github.com/datagen24/victual/pull/1066)). | The decision record for everything below: catalog and stock-count tools with no deletes, the chart setting the enabled tools, and an opt-in private-network Ingress, with public exposure staged behind Cloudflare Access and OAuth (issue 770). |
| The chart sets the sidecar's tools, and can publish it ([PR 1067](https://github.com/datagen24/victual/pull/1067)). | `mcp.enabledTools` (default `all-read`) replaces the hard-coded `MCP_ENABLED_TOOLS`, so enabling a write tool is a values change that survives an upgrade and rolls the sidecar. `mcp.ingress`, off by default, publishes exactly `/mcp` on its own hostname, with the same fields as `ingress`. New keyword `stock-write`. |
| Stock bookings are idempotent, and Victual's error text reaches the assistant ([PR 1068](https://github.com/datagen24/victual/pull/1068)). | Each booking asks `GET /api/system/info` first and sends ADR-0046's `Idempotency-Key` when Victual publishes it, returned as `request_id`. A retry after an unknown outcome with the same `request_id` and values replays instead of booking twice. A refused request's `error_message` now appears in the tool error. |
| Master-data lists and barcode lookup ([PR 1069](https://github.com/datagen24/victual/pull/1069)). | New reads in `all-read`, each needing `STOCK_VIEW`: `list_locations`, `list_quantity_units`, `list_product_groups`, `lookup_barcode`. The last falls back to the configured external lookup without `add`, so it creates nothing, and it returns no price field. |
| Catalog writes ([PR 1070](https://github.com/datagen24/victual/pull/1070)). | Off unless named or enabled with `catalog-write`: `create_product`, `update_product`, `create_location` (with an optional parent), `create_quantity_unit`, `create_product_group`, `add_barcode`. They need `MASTER_DATA_ADD`; `update_product` needs `MASTER_DATA_EDIT` and cannot change the stock unit. |
| Stock-count and list writes ([PR 1071](https://github.com/datagen24/victual/pull/1071)). | In `stock-write`: `inventory_product` (sets an absolute amount, and an unchanged amount books nothing), `open_product`, `transfer_product`, `undo_transaction`, `check_off_shopping_list_item`. No tool calls a delete route; a test holds that. |
| The Talos dev app runs every tool ([PR 1072](https://github.com/datagen24/victual/pull/1072)). | `deploy/talos/values.yaml` enables all three keyword groups and publishes the sidecar at `mcp.victual.10.130.34.240.nip.io` on the LAN. It is this repository's test deployment, not a default. |

## Database migrations

None. Nothing under `migrations/` or `db/` changed since `v0.5.3`. 0.5.4 expects the schema 0.5.3
left, at migration 318.

## Compatibility

- **Sidecar tools:** `all-read` grows from six tools to ten on upgrade. All writes stay off until
  `mcp.enabledTools` names them. Existing tool inputs and outputs are unchanged, except that
  `consume_product` and `purchase_product` gain `request_id` and `replayed` in
  `structuredContent`, which is additive.
- **Chart values:** `mcp.enabledTools` and `mcp.ingress` are new and optional. A values file that
  sets neither renders what 0.5.3 rendered, apart from comments.
- **Victual image:** unchanged apart from the version string. The REST API, permissions and
  schema are as in 0.5.3.

## Known limitations

Found in the dev conversations. None blocks the pantry walk.

- **No tool reads the stock journal.** `undo_transaction` needs the `transaction_id` a booking
  returned, so an assistant can undo only within the conversation that booked. A later
  conversation has to correct with `inventory_product`, which leaves a separate correction in
  the history.
- **A new product defaults to a best-before of 0 days.** Without `default_best_before_days`, its
  first counts are due the day they are recorded. Changing the default later does not change
  stock already on hand, and no tool edits an existing stock entry's due date.
- **`list_locations` returns every active location.** It has no filter or limit, which costs
  tokens on an instance with hundreds of locations.
- **A duplicate product name is reported generically.** Victual answers "The database rejected
  this request", which does not say that the name is taken. The tool description tells the model
  to check `find_product` first.
- **Phone access** is stage 3 of ADR-0052 decision 7. It needs OAuth (issue 770) and a route
  through Cloudflare Access. Clients on the household network work now.
