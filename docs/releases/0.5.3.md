# Victual 0.5.3

**Tag `v0.5.3`, on `master` at the commit that merges this record.** It follows
[0.5.2](0.5.2.md). It is a patch release, and the reason to install it is label printing: 0.5.2's
label designer could not produce a usable label for a typical continuous roll. 0.5.3 resolves
issue 1033 (orientation, element rotation and starter fonts), which was moved from 0.6.0 to 0.5.3
on 2026-10-22. It also fixes three defects found setting labels up on a production cluster, and
adds batch printing for a location tree. It changes no schema.

## What changed

| Change | Effect for an operator or client |
|---|---|
| QR-only labels are no longer refused as too short ([PR 1057](https://github.com/datagen24/victual/pull/1057), renderer [PR 1](https://github.com/datagen24/victual-label-renderer/pull/1)). | Automatic length ignored QR codes, so a QR-only label was as long as its bottom margin and endless media refused it with `MEDIA_INCOMPATIBLE`. QR symbols and their quiet zones now count. The editor's canvas also redraws as its size is typed. |
| Starter fonts ([PR 1058](https://github.com/datagen24/victual/pull/1058), issue 1033). | **Add starter fonts** in the template editor stores Noto Sans, Noto Sans Bold and Noto Sans Mono (SIL Open Font License 1.1) as label assets, so text can be added without uploading a font. The fonts ship under `services/Labels/StarterFonts/`, pinned by SHA-256. API: `POST /api/labels/assets/starter-fonts` (ADMIN), idempotent. A starter name already holding a different file is refused as `name_taken`. |
| Reading orientation ([PR 1059](https://github.com/datagen24/victual/pull/1059), renderer [PR 2](https://github.com/datagen24/victual-label-renderer/pull/2), issue 1033). | A template can be read turned 90°, 180° or 270° onto the tape, so a long label can be read sideways. Width stays the roll and length the tape. This is label template `schema_version` 2 (`canvas.orientation_deg`); schema 1 templates are unchanged and keep their digests. |
| Element rotation ([PR 1060](https://github.com/datagen24/victual/pull/1060), renderer [PR 3](https://github.com/datagen24/victual-label-renderer/pull/3), issue 1033). | Text, QR, image and rectangle elements can each be rotated in 90° steps from their properties (schema 2, `rotation_deg`). The editor uses a Rotation select, not a free rotate handle, because only quarter turns are valid. |
| Asset URLs change with every build ([PR 1061](https://github.com/datagen24/victual/pull/1061)). | Scripts and stylesheets are served `immutable` for 30 days, and every `?v=` was the version alone, so a redeploy of the same version left browsers on the previous build's scripts. `?v=` is now `<version>.<build token>`, a hash the Nix build writes from the application source and the frontend lock files. A checkout without a build token keeps the version alone. |
| Labels for everything under a location ([PR 1062](https://github.com/datagen24/victual/pull/1062)). | A location's edit page has **Preview** and **Print N labels** for every location under it. A location that already has a valid label is skipped unless reprinting is ticked, inactive locations are skipped, and the location itself is printed only when ticked. One transaction, at most 200 locations. API: `POST /api/labels/locations/{locationId}/print-subtree` with `include_root`, `reprint_existing` and `dry_run`, each false unless sent. |
| A new text element starts on a field its kind has ([PR 1063](https://github.com/datagen24/victual/pull/1063)). | Adding text to a stock entry template defaulted to `stock_entry.name`, which does not exist, and saving was refused. A new text element now starts on the kind's first catalogue field, `stock_entry.product_name` for stock entries. |
| Unit seeding for US, metric and mixed households ([PRs 1054](https://github.com/datagen24/victual/pull/1054) and [1055](https://github.com/datagen24/victual/pull/1055)). | `.devtools/seed/seed_units.py --system us\|metric\|both` loads quantity units and global conversions into a running instance through the API, add-only, with `--dry-run`. It is an operator tool, not run by the application; the [getting started](../manual/getting-started.md) page describes it. |

The renderer image is built from `datagen24/victual-label-renderer` at `96f00d0`, which
`flake.lock` pins and the CI agreement test builds.

## Database migrations

None. Nothing under `migrations/` or `db/` changed since `v0.5.2`. 0.5.3 expects the schema 0.5.2
left, at migration 318.

## Compatibility

- **Label templates:** schema 1 documents are accepted and re-emitted unchanged, so published
  versions and their digests are untouched. The editor writes schema 2 only for a design that is
  turned. A schema 2 template needs the 0.5.3 renderer; a 0.5.2 renderer refuses it as
  `UNSUPPORTED_VERSION`, so update the renderer image together with the app.
- **API additions:** `POST /api/labels/assets/starter-fonts` and
  `POST /api/labels/locations/{locationId}/print-subtree`. No existing route changes.
- **Browsers:** every asset URL changes once on upgrade, so clients fetch the new scripts without a
  hard reload.
- **Images, chart values and manifests** change in their version. Deployment paths,
  configuration and permissions are unchanged.

## Known limitations

- **A label takes about a minute and a half to print.** The renderer and the worker are CronJobs
  that run once a minute, so a print waits for the renderer's next run and then, because the
  worker ran at the same moment, for the worker's next one. A resident polling mode and
  [ADR-0026](../adr/0026-a-wake-signal-may-announce-label-work.md)'s wake signal are the options.
- **The renderer credential is issued from the browser console.** The label printers page issues
  only the worker credential; issue 1056 covers a renderer button and the setup order.
- **Four interface strings are missing from `localization/strings.pot`.** They are in the views
  ("Print a label for this product", and three tare-weight strings) but not the catalogue, so
  they cannot be translated yet.
- **Centre, guides and snap-to-grid** are issue 1034 (0.6.0).
- **Restore drill scope** is unchanged from 0.5.1: only `FILE_STORAGE` `database` was drilled.
- **Gate R6** (a production support claim for cluster labels and shutdown) stays unplaced.
