# 0.4.4 to 0.5.0 database upgrade rehearsal

Run date: 2026-10-19. Source tag `v0.4.4` resolves to
`631c6b27cf0d743b6068b5f503940ff9dc97e496`. The candidate was
`17f9f000b317e41d50b215afee2fef072d4f16b5`, the release branch's first commit. Its
`migrations/` and `db/` match `master` at `56abf0a0`. Both trees ran under PHP 8.5.10 from the
flake's development shell, against PostgreSQL 16.15. The script and fixture are in
[`.devtools/pgsql/upgrade-rehearsal/v0.5.0/`](../../.devtools/pgsql/upgrade-rehearsal/v0.5.0/).

Six migrations separate the two releases, 0313 to 0318. Two of them read existing data: 0313
refuses NaN and infinite values, and 0315 marks every stored price of 0 as unknown. The
fixture exercises both.

## Fixture

The v0.4.4 migrator created two databases at migration 312. In each, the v0.4.4
`StockService` and `ChoresService` then booked:

- `Upgrade audit oats`: 3 purchased at 2.50, then 1 consumed;
- `Upgrade audit salt`: 2 purchased at a price of 0;
- `Upgrade audit tea`: 1 purchased with no price;
- `Upgrade audit chore`: three executions.

The second database also had the oats row's price set to `NaN`, a value 0.4.4 could store.

## Valid database

The candidate migrator ran twice. Both runs exited 0 and reported
`Schema is up to date at migration 318.`

| Read | Before (312) | After (318) |
|---|---|---|
| Stock: oats, salt, tea | 2, 2, 1 | 2, 2, 1 |
| `stock` rows, `stock_log` rows | 3, 4 | 3, 4 |
| Chore executions | 3 | 3 |

Schema-only and data-only dumps after the first run and after the second were byte-identical.
Normalization removed only the per-run `\restrict` and `\unrestrict` lines.

| Dump | SHA-256 after run 1 and after run 2 |
|---|---|
| Schema | `3ef4037e358fb7c10aab066017eec05105c814c4c36634f038e1241f9fe52627` |
| Data | `e6a0251ae4a86dbdc0dba4354ffdf9f242d1900647a5283850f2f9d819007083` |

Migrations 0315 and 0316 read the prices as ADR-0045 intends. No stored price changed.

| Product | Stored price | `legacy_zero_price` | `stock_current.value` | `value_incomplete` |
|---|---|---|---|---|
| oats | 2.5 | 0 | 5 | 0 |
| salt | 0 | 1 | 0 | 1 |
| tea | NULL | 0 | 0 | 1 |

`price_interpretation_reports` holds one row: source `upgrade`, policy `unknown`, 1 `stock`
row and 1 `stock_log` row marked.

## Database holding a NaN

The candidate migrator exited 1 with
`Migration refused: 1 value(s) are NaN or infinite, which no numeric column may hold any more.`
The database stayed at migration 312, and the NaN row was still there. Full dumps before and
after the attempt were byte-identical after the same normalization:
`fab2de29ae4897857c38339a0e69f54dccfd97f8dd13b019ef111668d9e699f3`.

## Scope

This shows that a populated 0.4.4 database upgrades, that a repeat run changes nothing, and that
0313 refuses an unrepaired database without changing it. It does not test the production Nix
images, arbitrary household data, PostgreSQL 15 or restoring a backup. The `tests` workflow
runs the migration phase on PostgreSQL 15 and 16. The data-only dumps are comparison evidence,
not a restore test.

## Reproduce

```bash
git worktree add /tmp/v044 v0.4.4
# composer install --no-dev in both trees, inside `nix develop`
nix develop -c .devtools/pgsql/upgrade-rehearsal/v0.5.0/rehearse.sh /tmp/v044 "$PWD" /tmp/r050
```

The script drops and creates `r050_valid` and `r050_invalid` on the server it is given, so
point it at a scratch server. Its header lists the connection variables.
