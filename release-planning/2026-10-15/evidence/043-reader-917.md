# Reader report: #917 legacy importer precision

Baseline: `b728d0d1a2203523155327b89a03716f915b58c4`. Read-only GPT-6 Luna medium report from `/root/043_import_precision_reader`.

## Findings

`DatabaseImporter::CopyTable()` streams SQLite rows as `FETCH_ASSOC` values. SQLite REAL values arrive as PHP floats, remain unchanged by `SourceInstantsRead()`, and are flattened into array parameters for `$statement->execute($values)` without explicit PDO typing or round-trip serialization. PostgreSQL targets map SQLite REAL/DECIMAL to `DOUBLE PRECISION`. Under PHP `precision=14`, some finite values can lose binary64 digits before PostgreSQL parses them.

Source references at the named baseline: `services/Database/DatabaseImporter.php:1004-1043,1090-1100,1172-1188`; `services/Database/ValueComparison.php:23-55,62-65`; `db/pgsql/README.md:260,285-300`.

## Existing measured evidence

Issue #917 records validator run B comparing source `9.223372036854776e+18` (2^63) with target `9.2233720368548e+18`. The issue cites DBL_MAX and 2^63 and requests a 17-significant-digit regression case, but the validator command/head/fixture and the 17-digit result were not found in local evidence. No tests were rerun. The import phase is `.devtools/pgsql/run-tests.sh import`.

`ValueComparison::Normalise()` rounds numeric values to six decimal places before JSON row comparison. This can hide small discrepancies and cannot recover precision already lost at insertion. Exact fidelity needs a separate source-to-target round-trip assertion while preserving the differential harness’s intended normalization where applicable.

## Acceptance, rollback, existing data

No current finite-value preflight rejects the affected values. The importer replaces common-table rows only when an operator runs it; no schema migration is indicated. A corrected import can replace previously imported values with source doubles.

The issue’s “clean rollback” claim conflicts with inspected baseline control flow: `ImportSnapshot()` commits at `:884`, then calls row-count and value assertions at `:888-889`. The post-commit value mismatch exception is outside the transaction catch at `:874-882`, so that path cannot roll back there. Confirm whether the recorded validator used another head, an outer transaction, or external restoration. Add a test that checks target state after refusal or successful verification.
